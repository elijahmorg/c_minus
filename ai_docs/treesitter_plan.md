# Tree-sitter Grammar Implementation Plan (C-minus)

## Goal

Create a C-minus Tree-sitter grammar based on the existing C Tree-sitter grammar, with true C-minus semantics:

- `module`, `import`, `cimport`, and `pub` are first-class nodes
- Qualified type names like `ticket.Ticket` are parsed as type specifiers
- Qualified access like `ticket.create_ticket()` is parsed as a module-qualified call, not a field access

All Tree-sitter code and tests will live under `treesitter/`.

## Constraints

- C-minus grammar should be a fork/derivative of Tree-sitter C grammar
- No Tree-sitter grammar work outside `treesitter/`
- No timeline estimates

## High-level approach

1. Fork `tree-sitter-c` into `treesitter/` and rename it to `tree-sitter-cminus`
2. Add C-minus top-level constructs and `pub` modifier
3. Extend type specifiers to allow `qualified_type` (`module.identifier`) in declaration/type contexts
4. Use an external scanner to track imported module prefixes and emit a dedicated `module_identifier` token
5. Replace `field_expression` usage with module-qualified access where the token indicates a module prefix
6. Provide a corpus test suite and a `highlights.scm` query set

## Grammar changes (based on tree-sitter-c)

### 1) New top-level declarations

Add nodes before/alongside C declarations:

- `module_decl`: `module "path"`
- `import_decl`: `import "path"`
- `cimport_decl`: `cimport "path"`
- `pub_modifier`: optional modifier on function/type declarations

Placement rules:

- `module_decl` is allowed exactly once and must appear before any other top-level declaration

### 2) Qualified type names

Allow type specifiers to include:

- `qualified_type`: `module_identifier "." type_identifier`

This must be accepted in type contexts:

- variable declarations
- function parameter types
- return types
- struct field declarations

### 3) Qualified module access

Introduce:

- `module_qualified_identifier`: `module_identifier "." identifier`
- `module_qualified_call`: `module_qualified_identifier` followed by call expression

Enum values:

- Allow `module_identifier "." identifier "." identifier` (e.g. `state.State.IDLE`) as a module-qualified enum value access

This should be used in expression rules to avoid parsing as field access.

### 4) External scanner (key for semantics)

Implement a scanner to track module prefixes:

- When it sees `import "path"` or `cimport "path"`, record prefix = last path segment
- Only record prefixes when the last path segment contains no `.` (e.g. `foo.bar/baz` ok, `foo.bar/baz.qux` not allowed)
- Exception: for `cimport`, allow a final segment ending in `.h` and strip the extension (e.g. `stdio.h` -> `stdio`)
- Emit a dedicated `MODULE_IDENT` token when an identifier matches a recorded prefix
- The grammar uses `module_identifier` token for qualified access/type names

This mirrors the approach used by tree-sitter-c for `typedef` names.

## Tests

### Corpus tests (`tree-sitter test`)

Add deterministic tests for positive and negative cases:

Positive cases:

1. Module/import/cimport declarations (module only once at top)
2. Qualified types in declarations
3. Qualified calls in expressions
4. Enum qualification: `state.State.IDLE`
5. C compatibility (ensure ordinary C parses are unaffected)

Negative cases:

1. `module` appearing after another top-level declaration
2. Qualified access when the module prefix was not imported
3. `import` paths with a `.` in the last path segment (no module prefix should be recognized)
4. `cimport` paths with a `.` in the last path segment that is not `.h` (no module prefix should be recognized)
5. Field access should remain `field_expression` when no module prefix is recorded

Each test file should include:

- Input snippet
- Expected parse tree (S-expression)

### Query tests

Add `queries/highlights.scm` and verify captures using:

- module/import keywords
- module-qualified identifiers
- type identifiers in qualified types
- public declarations (`pub`)

## Highlighting query plan

`highlights.scm` should define captures for:

- `module`, `import`, `cimport`, `pub` as `keyword`
- `module_identifier` as `namespace`
- `qualified_type` as `type`
- function names as `function`
- `enum`/`struct`/`typedef` as `type`

## Build/test workflow

- Generate parser with `tree-sitter generate` inside `treesitter/tree-sitter-cminus`
- Run tests with `tree-sitter test`

## Decision points

- Import prefix rule: use last path segment only when it contains no `.` (e.g., `foo.bar/baz` -> `baz`)
- Cimport prefix rule: allow `.h` in the last segment and strip it (e.g., `stdio.h` -> `stdio`)
- Qualified enum access (`state.State.IDLE`) should parse as `module_identifier "." identifier "." identifier`
- Keep C grammar compatibility by deferring to original C rules when no module prefix is detected

## Deliverables

- `treesitter/tree-sitter-cminus/` with grammar, scanner, and queries
- Corpus tests covering C-minus constructs and C compatibility
- `ai_docs` documentation updates only if explicitly requested
